# 应用申请包存储：开发者使用边界

应用开发者通过 AgentCiCi 管理接口提交、查询和下载申请包，不直接访问 OSS、数据库或平台磁盘。包的存储介质、访问控制、共享目录和清理策略由平台维护；本技能不要求创建平台 backend/frontend/deploy 工程，也不索取云存储 AK。

## 提交与恢复

- 本地 package/validate 只生成和校验包，不能证明目标服务已部署或具备存储能力。
- submit 成功以服务端申请 ID、状态和原包 SHA-256 为准，保留非敏感回执在应用 docs 或本机 release 目录。
- 同组织同原包摘要支持幂等提交；上传结果未知先查询申请或重交同一原包，不重新打包冒充相同请求，不覆盖已发布版本。
- 服务端报告上传或存储失败时记录失败；不得用本机包存在、静态站点可打开或 HTTP 200 代替业务成功状态。
- 版本过期、文件不可下载、清理待完成等以目标服务返回为准。已有服务可能保留最近5个不同版本，但不据此从应用脚本自行批量删除包或其他组织资源。

## 发布与安装

申请包持久化、创建草稿、组织发布和 CRM 安装是不同阶段，分别确认结果。静态资源路径由平台发布和安装runtime提供，不猜测磁盘路径或将开发机配置路径交给安装者。

若目标服务确有存储或发布故障，保留请求ID和脱敏错误作为平台问题线索；普通AI应用开发任务不自动扩大为云资源、Nginx或平台服务部署。只有用户明确授权平台运维时才使用对应运维流程，平台的私密配置与历史验证证据不写入可分发技能或应用包。
