# CloudCC CRM Web UI 规范

开发 AI Web 页面前必须阅读本规范，按同一套颜色、字号、控件密度和操作布局实现。适用于 CRM 内嵌菜单页、列表/详情页侧栏、SDK 对话框和独立本地测试页面。页面使用原生 Web（HTML、CSS、JavaScript），视觉和交互保持一致。

## 依据与取值原则

本规范于 2026-10-10 从参考项目 `one-main-web`（提交 `d7d1f4b0577a`）和 [CRM 商机列表页](https://ap6.lightning.cloudcc.cn/#/commonObjects/views/table/Opportunity/opportunity/002) 提炼。

| 依据 | 已确认内容 |
|---|---|
| `src/style/variables.scss` | 主色、状态色、文字色、边框、4px 圆角、14px 基准字号、32px 控件高度 |
| `src/style/common.scss`、`element-ui.scss` | 字体、蓝色链接、12px 表单标签/选择项、浅灰 tooltip |
| `src/modules/ListModule/index.vue` | 左右分组工具栏、20px 横向内边距、15/16px 工具栏上下留白、选择后的批量操作 |
| `src/modules/ListModule/TablePanel/index.vue` | 36px 表头/数据行密度、6px 单元格上下 padding、浅灰表头、分隔线、省略文本 |
| `src/modules/ListModule/HotButton/index.vue` | 32px 蓝色主按钮、4px 圆角、下拉分割按钮、hover/focus 状态 |
| `src/style/dialogStyle.scss` | 标题/内容/底部三段式弹窗、分隔线、14px 加粗标题、16px 垂直 padding |
| 本次真实页面截图 | 白色内容区、左侧刷新/筛选/视图/搜索、右侧新建/更多、蓝色记录链接、底部统计和分页 |

源码数值按 CSS px 使用；截图可能受显示器像素比与浏览器缩放影响，不按截图物理像素直接换算 CSS。参考仓库包含历史局部覆盖：主按钮统一按主题变量 `#2D6CFC`，不把旧弹窗最后一个按钮的 `#006DCC` 当作全局主色；表头使用列表组件的 `#FAFAF9`，不把变量默认 `#FCFCFC` 当作该页面的最终值。表单和弹窗规则本次来自源码，未宣称通过真实表单截图复验。

下文中标为“建议”的尺寸或行为是为新应用补齐的一致性规则，其他明确取值来自上述源码；目标 CRM 经核验的组件覆盖优先于通用基线。参考项目路径仅用于来源追溯，使用本技能不要求本机存在该仓库，也不读取平台源码作为应用开发前置条件。以下明确尺寸是本技能应用规范；标为建议的项目不能当作硬门禁。

## 颜色与基础尺寸

| 用途 | 值 | 使用方式 |
|---|---|---|
| 主操作/选中态 | `#2D6CFC` | 主要按钮、当前页码、选中强调 |
| 记录链接 | `#006DCC`，hover `#027EEB` | 可打开的记录、业务文本操作；与主按钮色分别使用 |
| 成功/警告/失败 | `#00BC68` / `#FE8A14` / `#F11B21` | 业务结果和校验状态，同时显示文字或图标 |
| 主要/常规/次要文字 | `#080707` / `#393939` / `#5F5E5E` | 数据和标题/说明/辅助信息 |
| 占位文字 | `#BBBBBB` | 输入占位和非关键提示，不用于重要正文 |
| 页面内容/基础灰底 | `#FFFFFF` / `#F5F5F5` | 内容面板/外围和轻量次级区域 |
| 控件边框 | `#E1E1E1`，hover `#BBBBBB` | 1px 实线 |
| 列表表头/分隔线 | `#FAFAF9` / `#EEEEEE` | 表头底色、表格横线与表头竖线 |
| 内容面板外边框 | `#DEDCDA` | 列表外框，保持细线 |
| 默认/小圆角 | `4px` / `2px` | 控件/小型元素；列表外框可按现有组件使用 3px |
| 控件高度 | `32px` | 按钮、搜索框、单行输入与选择器保持同高 |
| 表头/普通数据行 | `36px` | 紧凑单行表格基线，内容需要多行时允许增高 |

## 字体、间距与容器

- 基准文字 14px；表单标签、选择项和辅助文字可用 12px，与参考组件对应。弹窗标题 14px 加粗。建议独立页面标题 16–18px、普通文字行高 20–22px；避免大标题占据业务工作区。
- 左对齐为主，列标题与数据起点一致；长文本省略并提供完整查看方式，详细内容和错误正文可换行。避免用大字号或大块彩底区分所有层级。
- 列表工具栏横向 padding 20px，上下 15/16px；按钮间距建议 8px，分组间距建议 12–16px。普通内容区 padding 建议 16–20px。
- 页面以白色主内容和细灰线组织层级；一般面板不加重阴影，浮层才用轻阴影。建议不使用大圆角卡片、大面积渐变、装饰性横幅或营销式首屏。
- CRM 顶栏、左导航、全局浮点及关闭按钮由宿主/公共 SDK 管理。嵌入页只画自己的内容，不再复制整套 CRM 导航或新增一个全局悬浮入口。必要的业务侧栏放在应用容器内。
- 容器随可用宽高伸缩，表格区承接剩余空间，分页和主操作保持可达。建议使用 flex 与 `min-height: 0` 控制滚动，避免整页和多个嵌套容器同时出现滚动条。

## 列表与工具栏

- 上方一条操作栏：左侧按刷新、筛选、视图切换、展示模式、搜索的顺序组织已有功能；右侧放首要业务操作及更多操作。只显示本应用需要的功能，不为模仿页面而创建无效按钮。
- 主操作用蓝底白字，次要操作用白底灰边框；图标按钮同为 32px 高，建议图标 14–16px 并有 tooltip/可访问名称。一个操作组只突出首要动作。
- 支持下拉的主操作采用分割按钮：主要动作和展开按钮分别可点；常规选项用下拉菜单，不堆成一排高亮按钮。
- 搜索框与按钮同高，提示说明搜索范围；建议支持 Enter 搜索。有刷新/筛选/排序时保留当前条件，并明确筛选生效状态。
- 数据行使用白底、细横线；表头浅灰、文字加粗，竖线主要用于表头分列。普通记录默认单行、省略显示；可打开的名称用蓝色链接。不要把所有阶段或普通文本都变成彩色标签。
- 采用 36px 表头/行基线：参考组件单元格上下 padding 6px、内容 min-height 23px。不固定更大高度以制造留白；含多行内容时按业务需要增高。
- 截图中的金额和日期为左对齐；需做数值比较时可建议金额列右对齐，但同一列标题与数据对齐方式必须一致。金额包含币种和千分位，日期格式遵循 CRM 用户语言/区域设置。
- 选择列、序号列在左；选中数据后显示已选数量与批量操作，不让原筛选操作和大量批量按钮挤在一起。选择态不能只依赖颜色。
- 底部左侧显示总条数及有依据的统计，右侧显示页码、上一页/下一页、每页条数和跳页；只展示有实际分页/统计能力的控件。页面数据少时也保持统一底部布局，不伪造总数。

## 表单、弹窗与侧栏

- 单行字段沿用 32px 高、1px 边框、4px 圆角；同一行字段和按钮对齐。标签可用 12px；建议短表单纵向排列，宽容器可双列，长文本字段占整行。
- 必填标记与标签一起显示；建议错误紧邻字段且保留输入，不能仅弹 toast。占位文本用于示例，不能替代字段标签。
- 弹窗使用标题、内容、操作底部三段结构，顶部右侧关闭；标题/内容/底部之间用细线。参考样式标题 padding 为 `16px 14px 16px 36px`，内容与底部为 `16px 36px`；小尺寸 SDK 对话框可适当减小横向 padding，保持同一密度。
- 底部操作靠右，建议次要“取消”在左、蓝色主要动作在右；按语义决定按钮样式，不用“最后一个按钮必为蓝色”的 CSS 选择器。
- SDK 已提供标题或关闭入口时不要重复绘制。弹窗宽高与展示位置来自应用入口清单；正文可滚动，操作区不得被截断。不能为视觉适配私自改 SDK 外壳。
- 侧栏沿用相同字体、控件和间距，收紧布局但不挤压文字；避免把独立页面的宽表格原样塞入窄侧栏。

## 交互、状态与样式隔离

- 主按钮 hover/focus 参考主色与白色混合 20% 的浅化状态；禁用和运行中应明确区分，防止重复提交。建议给键盘焦点可见边框，不仅用 hover 表示可操作。
- 下拉项 hover 使用浅灰或浅蓝底；tooltip 参考浅灰 `#DDDCDB`、深色字 `#303133` 和轻阴影。提示必须可读，不照搬低对比文字作为正文。
- 建议至少覆盖初次加载、空数据、无搜索结果、权限不足、请求失败、成功、运行中和取消状态；不要用空白表格掩盖异常。危险操作用红色语义并清楚说明影响。
- 使用语义按钮、输入标签与可访问名称；状态色搭配文字，不以颜色作为唯一依据。对比度与键盘操作需实际检查，不能因接近 CRM 就声称符合完整无障碍标准。
- iframe 内样式定义在自己的文档；Shadow DOM 内显式设置字体和变量。应用根节点之外不得注入 `body`、`html`、`.el-button`、`.el-table` 等全局覆盖，避免污染宿主及其他 AI App。
- 可复用适用于原生 Web 的现有组件；按本规范设置视觉变量，不复制参考项目的整个主题 CSS、运行凭据或业务数据。

## 开发与桌面验收

1. 开始编码前确定入口类型、可用容器与首要业务操作，读取本规范并建立应用自己的样式变量。
2. 开发后在实际 CRM 容器或同等尺寸的本地容器查看页面；建议至少 1280×720 与 1440×900，浏览器缩放 100%，不把 iframe 误当作整个浏览器视口。除用户另行要求，本规范只做桌面验收。
3. 并排对照 CRM 列表：主色、字体、32px 控件、36px 表格密度、4px 圆角、工具栏分组和底部操作位置应保持协调。
4. 检查长名称、多列数据、筛选、选择、分页、loading、错误、禁用、键盘焦点及窄侧栏/小弹窗；有相应功能才测试，不为验收新增无关功能。
5. 检查嵌入后没有重复导航、全局浮点或关闭按钮，没有遮住 CRM 工具栏、修改宿主样式或超出容器。确认 API 地址仍遵守 apiBase 规范。
6. 用真实渲染结果验收。记录实际检查与未覆盖项；截图只作授权范围内的验证证据，交付规范和示例必须使用占位内容，不保存真实客户记录、用户信息或 Token。
